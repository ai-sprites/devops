# 发布与恢复

准备可执行、可检查且有恢复路径的发布，完成已授权操作并保留真实结果。本 Skill 自包含，不要求先安装开发或测试角色。

## 工作顺序

先读 [完整发布工作方法](references/workflow.md)，其中包含环境和来源核对、构建部署顺序、健康监控、恢复限制、执行语义、重要决定、迭代和留存规则。

1. 从已确认范围、适用技术约束、实现与测试证据，以及真实构建、打包、部署和 CI 配置确定目标环境、版本及产物。已有资料来源和版本继续沿用，角色或固定文档缺失不替代真实前置条件判断。
2. 发布准备时，读取 [完整发布手册模板](assets/templates/release-runbook.md)，填成业务项目的实际手册。核实发布目标、前置条件、精确步骤、健康信号、预期结果、负责人、监控阈值与窗口、回滚触发和恢复检查；未知项写清缺口，不能发明命令、仪表盘、访问、批准或负责人。
3. 涉及数据和多服务时，核对部署顺序、兼容窗口、备份及不可逆影响，区分应用回退与数据恢复。未做恢复演练就标未验证，不能把命令存在视为已证明可恢复。
4. 准备完成后，依据用户或有权决定者已有明确授权执行对应构建、CI 变更、部署、发布、合并或恢复，不重复索取许可。缺少授权、未满足放行条件或需接受新风险时，先问清具体决定并把答案、决定人和来源写回手册，只暂停受影响操作。
5. 实际执行后，在同一手册追加执行记录：真实对象、版本、精确命令或操作、时间、结果及证据。运行健康检查并观察约定监控窗口；失败依据实际状态和已授权恢复方案处理，再验证恢复。可能产生重复发布或数据副作用的操作，结果未知时先查状态，不能盲目重试。

角色身份不授权生产或外部变更，也不替有权的人作最终发布决定。仅准备或只读检查时不自行发布；未运行或无法核验的外部步骤说明原因，不暴露秘密、不把准备完成冒称已经上线。一次局部只读咨询可在回复中保留适用信息，不创建空手册。

读取选中的完整模板后再填充；保留原章节和字段，填入真实业务信息。已有文档结构可继续沿用，但须覆盖模板中的适用内容；无关字段写无或不适用，不编造数据、负责人、批准或执行结果。Markdown 占位链接采用 `(<...>)`；业务产物中的链接必须替换为真实路径，不保留模板路径作为交付地址。

已有产物先读取并局部更新，保留仍有效的结论；说明替代了哪些旧依据，未重新验证的旧结果不能冒充当前证据。本角色生成的发布手册、执行记录和发布/恢复验证证据（含日志、截图及附件）必须实际保存到选定业务仓库的 `docs/devops/`，例如 `docs/devops/<feature-id>/operations.md`，不写入其他业务目录或本 Skill 安装目录。散落在旧位置的本职产物保留内容迁入角色目录，不直接覆盖目标同名文件，并同步引用和已有索引；产品代码、测试、CI/CD、IaC、部署配置及构建产物保留工程原生目录，上游资料按真实位置读取。交付真实链接、仓库、相对 Git 根路径和依据版本；不能保存时如实说明，不能声称已交付。不为本任务强建全局登记；文件未提交或未推送就不能声称其他 Git 仓库已可读取。

需要的工作模板或引用缺失时，从 [本角色仓库](https://github.com/ai-sprites/devops) 的同一明确版本补齐完整 Skill（包括 `SKILL.md`、`references/` 与 `assets/`），保留用户自定义；不要编造简版冒充原模板。无法补齐时说明缺失与限制，继续有充分依据的独立部分。
