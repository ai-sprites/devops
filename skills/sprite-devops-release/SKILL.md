# 发布与恢复工作流

准备可执行、可检查且有恢复路径的发布，完成当前已授权操作。总入口、三个阶段和共享参考组成完整流程，不要求先安装开发或测试角色。

## 工作顺序

```text
请求 / 目标版本 / 真实构建部署配置 / 测试证据
        │
PREPARE sprite-devops-prepare  → 可执行发布手册与已知缺口
        │ 已有明确执行授权且条件满足
EXECUTE sprite-devops-execute  → 构建、发布、健康与监控证据
        ├─ 成功 → 交付实际结果
        └─ 失败 / 恢复请求
RECOVER sprite-devops-recover  → 核对状态、按授权恢复、验证结果
```

| 阶段 | 输入 | 完成条件 |
| --- | --- | --- |
| [Prepare](../sprite-devops-prepare/SKILL.md) | 已确认范围、版本、配置和实现/测试证据 | 目标、前置条件、精确顺序、健康、监控及恢复安排有依据 |
| [Execute](../sprite-devops-execute/SKILL.md) | 可执行手册、已授权目标与满足的执行条件 | 操作、版本与时间可查，健康检查及约定观察窗口有结果 |
| [Recover](../sprite-devops-recover/SKILL.md) | 失败证据或恢复请求、当前状态和恢复约束 | 恢复后验证完成，或明确未恢复部分、影响与所缺决定 |

已有有效手册可以直接 Execute，已有故障或恢复任务直接 Recover，只补受影响的准备。只读咨询、评审或盘点已有成果不启动发布；准备任务不自动扩大成执行任务。

## 执行规则

1. 所有命令、目标、前置条件、健康信号、阈值、窗口和负责人从真实项目与已有决定获取，未知项列明影响，不编造访问、批准、仪表盘或成功结果。
2. 已明确授权的构建、CI/配置变更、发布、合并或恢复，准备完成并满足条件后继续执行，不重复索取许可。角色身份不扩大生产或外部变更权限，也不代作最终发布或实质风险接受决定。
3. 数据和多服务变更核对兼容窗口、执行顺序、可用备份与不可逆影响；应用回退与数据恢复分开，没有演练不能承诺可恢复。
4. 结果未知先查实际状态，可能重复发布或产生数据副作用的操作不能盲目重试。
5. 实际操作后验证健康并观察约定窗口；失败按状态与已授权恢复方案处理，再验证恢复。准备完成、已发布、已恢复分别由证据支撑。

具体方法见 [工作方法](references/workflow.md)。缺少必须的决定、证据或访问只暂停受影响操作，其余准备继续。

## 产物

沿用项目已有手册和证据位置；无约定时可采用以下目录：

```text
docs/devops/<feature-id>/
├── operations.md   发布手册、决定和实际执行/恢复记录
└── evidence/       健康检查、监控、日志、截图及必要附件
```

发布准备维护可执行手册，实际操作后在同一手册追加记录；历史文档原位维护，局部只读咨询不强建空文档。需求、版本与测试证据通过现有 Jira、文档、代码或 CI MCP 按需获取，本地和用户材料同样可用。产品代码、测试、CI/CD、IaC、部署配置及构建产物保持工程原目录。

## 全流程完成检查

- [ ] 目标环境、版本和实际产物明确，来源与适用技术约束可追溯。
- [ ] 精确步骤、前置条件、健康信号、监控窗口、异常动作与恢复限制明确。
- [ ] 在已有授权内完成对应工作；未决项保留影响、决定人或下一项检查。
- [ ] 实际操作、健康/监控/恢复检查及未验证项有真实记录。
- [ ] 手册与证据有真实可用链接，未完成项明确。
