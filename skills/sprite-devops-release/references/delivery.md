# 发布模板与交付

## 使用完整手册

发布准备时读取 [完整发布手册模板](../assets/templates/release-runbook.md)，填成业务项目的实际手册。核实发布目标、前置条件、精确步骤、健康信号、预期结果、负责人、监控阈值与窗口、回滚触发和恢复检查；未知项写清缺口，不能发明命令、仪表盘、访问、批准或负责人。

实际执行后在同一手册追加执行记录：真实对象、版本、精确命令或操作、时间、结果及证据。准备、发布与恢复状态分别依据实际证据填写。一次局部只读咨询可在回复中保留适用信息，不创建空手册。手册必需内容与资料桥接规则见 [工作方法](workflow.md#交付) 和 [产物留存与交接](workflow.md#产物留存与交接)。

## 填写、保存与维护

读取选中的完整模板后再填充；保留原章节和字段，填入真实业务信息。已有文档结构可继续沿用，但须覆盖模板中的适用内容；无关字段写无或不适用，不编造数据、负责人、批准或执行结果。Markdown 占位链接采用 `(<...>)`；业务产物中的链接必须替换为真实路径，不保留模板路径作为交付地址。

已有产物先读取并局部更新，保留仍有效的结论；说明替代了哪些旧依据，未重新验证的旧结果不能冒充当前证据。本角色生成的发布手册、执行记录和发布/恢复验证证据（含日志、截图及附件）必须实际保存到选定业务仓库的 `docs/devops/`，例如 `docs/devops/<feature-id>/operations.md`，不写入其他业务目录或本 Skill 安装目录。散落在旧位置的本职产物保留内容迁入角色目录，不直接覆盖目标同名文件，并同步引用和已有索引；产品代码、测试、CI/CD、IaC、部署配置及构建产物保留工程原生目录，上游资料按真实位置读取。交付真实链接、仓库、相对 Git 根路径和依据版本；不能保存时如实说明，不能声称已交付。不为本任务强建全局登记；文件未提交或未推送就不能声称其他 Git 仓库已可读取。

需要的工作模板或引用缺失时，从 [本角色仓库](https://github.com/ai-sprites/devops) 的同一明确版本补齐完整总流程与所需同级阶段（包括各自 `SKILL.md`、共享 `references/` 与 `assets/`，依赖范围见 [接入手册](https://github.com/ai-sprites/devops/blob/main/docs/installation.md)），保留用户自定义；不要编造简版冒充原模板。无法补齐时说明缺失与限制，继续有充分依据的独立部分。
