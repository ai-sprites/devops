# 发布模板与交付

## 维护可执行手册

优先更新项目已有发布手册。没有手册时参考 [发布手册模板](../assets/templates/release-runbook.md)，按本次发布范围填写适用内容，不为无关字段造信息。

手册应能说明目标环境与版本、前置条件、精确步骤、健康/监控检查及恢复办法。命令、阈值、窗口、访问和批准来自真实项目配置或已有决定，缺项说明影响。实际执行后在同一手册记录对象、版本、命令/操作、时间、结果和证据；准备、发布、恢复状态分别依据事实填写。

局部只读咨询可直接回复，不强建手册。已有记录局部更新，保留有效历史，未复验的旧结果不能冒充当前证据。

## 保存与交接

手册、执行记录和证据沿用项目已有位置；没有约定时可用 `docs/devops/<feature-id>/operations.md`。历史文档原位维护。日志、CI artifact、监控或截图可直接链接实际位置，只有任务需要时才保存脱敏副本；不能保存或访问时说明限制。代码、CI/CD、IaC、部署配置与构建产物保持工程原目录。

需求、发布范围、版本和测试依据通过现有 Jira、文档、代码或 CI MCP 按需读取，或直接使用本地和用户提供的材料。记录本次实际来源和版本，不要求资料集中存放或准备独立资料仓库。

交付当前状态、目标与版本、验证结果、真实手册/证据链接以及剩余影响。按任务需要关联已有 Jira 工单；写入后核验结果，结果未知先查询状态，不盲目重复创建或发送消息。文件尚未提交或无法远端访问时如实说明。

## 缺失资源

需要的技能参考或模板缺失时，从 [本角色仓库](https://github.com/ai-sprites/devops) 的同一明确版本补齐所需资源，保护用户自定义；无法取得时说明限制，继续有充分依据的准备。项目已有可用手册无需为使用技能重新套版。
