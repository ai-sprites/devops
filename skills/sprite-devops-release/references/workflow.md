# 发布运维工作方法

准备可执行且有恢复路径的发布，完成当前已授权操作，核验并记录真实结果。

## 准备工作

1. 按需读取当前请求、项目构建部署配置及已有发布记录。需求、版本、测试证据可通过现有 Jira、文档、代码或 CI MCP 获取，本地和用户提供的材料同样可用。确认目标环境、提交/构建与实际产物对应，不代写产品、架构或测试决定。
2. 核实真实命令、目标对象和必要访问、检查与批准，写出构建、打包、部署和验证顺序。多服务或数据变化核对兼容窗口、执行顺序与可用备份，区分应用回退和数据恢复。
3. 沿用项目健康信号、阈值、观察窗口和异常动作，记录依据。对本次发布必要而未知的条件写清缺口，不能发明仪表盘、负责人或发布门槛。
4. 确定恢复触发、步骤与恢复后验证；注明不可逆影响、备份可用性及未演练部分。回退命令存在不等于已证明能恢复。
5. 缺少关键访问、检查、备份或决定时只暂停受影响执行，其余准备继续。秘密只引用安全位置，不写进手册或日志。

## 执行与职责边界

沿用用户或项目有权决定者对目标、范围和条件的已有明确授权；准备完成且条件满足后继续执行，不重复索取许可。只要求准备或评审时交付对应结果，不自行触发发布。

未满足放行条件、目标变化或出现需要接受的新风险时，说明具体影响并取得必要决定；不将角色身份、未回复或建议视作批准。普通部署细节按项目约定处理，不建立额外审批流程。

执行记录包含真实对象、版本、操作、时间和结果。未知结果先查实际状态，可能重复发布或产生数据副作用的动作不能盲目重试。发布后完成健康检查和约定监控；失败时按实际状态和已授权恢复路径处理，再验证恢复。

## 交付

在项目已有手册记录本次适用内容：

- **目标与状态：**环境、版本/提交/构建及实际产物，区分准备、已发布和已恢复。
- **前置条件与操作：**必要访问、检查、批准和备份的当前状态，以及核实后的顺序和精确步骤。
- **验证：**健康信号、检查方法、监控阈值及观察窗口，附实际结果和证据。
- **恢复：**触发条件、步骤、恢复后检查，以及不可逆影响和未演练限制。
- **未完成事项：**剩余影响、缺少的条件或决定及下一步；没有则省略。

手册与记录沿用原位置，无约定时可用 `docs/devops/<feature-id>/operations.md`；证据可以链接现有 CI、日志和监控位置。变更只更新受影响部分，不强迁移历史文档或重做其他角色工作。详见 [模板与交付](delivery.md)。

交付先说明实际状态、目标版本、验证结果和剩余影响。没有执行证据不能声称上线，未演练不能声称可恢复。局部只读咨询可直接回复，不创建空文档。
