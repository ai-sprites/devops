# EXECUTE — 执行并验证发布

**输入：**有效发布手册、用户或有权决定者已明确的目标与执行授权、满足的前置条件及当前环境状态。

**输出：**授权范围内的真实操作结果，以及项目现有手册中的执行、健康与监控记录和必要证据。

## 1. 核对本次目标与执行条件

读取请求、真实发布手册、实际构建部署配置及当前环境，确认目标、版本、产物、兼容要求与已获授权一致。按 [工作方法的执行与职责边界](../sprite-devops-release/references/workflow.md#执行与职责边界)保留决定人和来源；明确授权的构建、CI/配置变更、发布、合并在准备完成且条件满足后继续，不另起批准流程。

核对当前检查、访问、环境值、备份及放行条件。手册和环境已变化时仅回 [PREPARE](../sprite-devops-prepare/SKILL.md)更新受影响部分。只读、评审或准备任务不能自动触发发布；“继续”沿用已明确任务，不能扩大目标和范围。

## 2. 按真实顺序执行并记录

按已核实步骤执行对应构建、打包、部署或配置变更，逐步记录实际对象、版本、精确命令/操作、时间与结果。多服务或数据变更遵守兼容窗口和已确认顺序，恢复约束不能由应用回退命令代替。

出现未满足条件、目标变化或新的实质风险时，说明影响并沿用或获取相应人的决定，只暂停受影响操作；答案、决定人及来源写回手册。输出、日志、配置示例和证据不包含秘密，不编造执行或外部系统结果。

## 3. 先查不确定状态，再决定下一步

命令超时、连接中断或外部系统没有明确返回时，将结果标为未知并查询实际状态。可能重复发布、合并或产生数据副作用的操作不能盲目重试；确认已生效、未生效或部分完成后再依据真实状态与既定方案继续。

无法核验的外部步骤单独记录原因、影响和下一项检查，不把工具已接受命令当成业务目标已完成。发生失败时保留首次失败证据，按实际状态交接 [RECOVER](../sprite-devops-recover/SKILL.md)，已有恢复授权直接沿用。

## 4. 验证健康并观察约定窗口

运行手册中的健康检查，核对信号、预期结果及实际产物/版本，观察约定监控窗口和阈值。附真实查询、日志或其他必要证据；未完成观察窗口或无法验证的项保持未验证，不提前宣称发布健康。

异常时依照实际状态和已授权方案恢复，完成恢复后继续相应检查。结果分别说明已部署、健康检查/监控结果和已恢复状态，不能只用命令退出码替代全部结论。

## 5. 更新同一手册并交付

按 [模板与交付](../sprite-devops-release/references/delivery.md)在同一手册追加执行与验证记录，保留仍有效的旧内容、标出替代依据及未验证项。手册原位更新，日志、截图和附件沿用项目位置并提供真实链接；代码、CI/CD、IaC、部署配置和构建产物保持工程原生目录。

先说明当前准备/受阻/已发布/已恢复状态、目标与版本、检查结果及遗留事项。文件未提交或未推送不能声称其他 Git 仓库可取；不能落盘或访问时如实说明，继续独立工作。

## 完成条件与下一步

- 授权对象、版本与实际操作一致，命令、时间、结果及决定来源可核验。
- 健康检查和约定监控窗口有真实结果；失败、未知和未验证项未被隐藏。
- 恢复分支如适用已验证，执行记录与必要证据可交接。

成功则交付发布结果；失败继续 [RECOVER](../sprite-devops-recover/SKILL.md)完成当前已授权恢复与验证，缺失决定只阻止相关操作。
