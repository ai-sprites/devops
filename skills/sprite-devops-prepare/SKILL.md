# PREPARE — 准备发布手册

**输入：**当前请求、已确认范围、目标环境/版本、实际工程配置以及实现与测试证据。

**输出：**`docs/devops/<feature-id>/operations.md`：可执行的发布手册、恢复安排和明确缺口。仅局部只读咨询可在回复中记录适用内容。

## 1. 确认真实来源与发布对象

读取请求、项目约定、README、已确认架构与开发方案、测试证据，以及实际构建、打包、部署、环境与 CI 配置。定位目标环境、提交/版本、实际产物及必须保留的兼容行为，保留真实来源和固定版本；已观察实现、待定建议不能代替已确认要求。

阅读 [完整工作方法](../sprite-devops-release/references/workflow.md)的准备工作与执行边界。其他角色或固定格式文档缺失不阻碍证据充分的工作，不代写缺少的产品、设计、架构或验收决定。已有来源和答案直接沿用。

## 2. 核实前置条件与执行顺序

确认项目真实命令、目标对象、执行工具、访问、环境值、检查、批准及必要备份，写出构建 → 打包 → 部署 → 验证的实际顺序。每步包括精确命令或操作、目标、条件和可核验结果；不发明命令、权限或已获批准，秘密只引用安全位置。

数据或多服务变更核对兼容窗口、部署顺序与备份。识别哪些旧版本仍在读写以及哪些变更不可逆，区分应用回退和数据恢复；不要因为已有一个回退命令就认为数据能恢复。

## 3. 准备健康、监控与恢复检查

找到真实健康信号、预期结果、检查方法及负责对象；沿用项目已有监控指标、依据充分的阈值、观察窗口与异常动作。未知阈值、负责人或窗口写明待确定及影响，不凭经验造发布门槛。

明确回滚/恢复触发、实际步骤及恢复后的检查，核对备份是否可用、恢复范围和无法恢复的影响。未演练项如实标未验证，恢复命令存在不等于恢复可用。手册应能让执行者知道何时继续、何时先查状态、异常时按哪条已授权路径处理。

## 4. 写入手册，处理具体缺口

按 [模板与交付](../sprite-devops-release/references/delivery.md)读取完整发布手册模板，保留原章节与字段、填真实信息；已有手册结构可沿用但须覆盖适用内容。需要的批准、访问、环境、检查、备份或外部步骤缺失时列明来源、影响及应处理的人或角色；只暂停受影响执行，独立准备继续。

先核对已有来源、决定和授权，仍需要人的决定才说明具体问题、为何现在需要及所影响操作，收到答案后写回选择、决定人和来源。已有授权不重复申请，建议和未回复不当批准，不让角色身份扩大执行范围。

保存业务仓库中的实际手册和必要附件，给出真实链接、仓库、根目录相对路径与依据版本。旧产物先读后局部更新或迁入 `docs/devops/`，保留有效内容、避免覆盖同名文件并同步引用及已有索引；产品代码和配置留在工程原目录。

## 完成条件与下一阶段

- 目标、来源、版本、真实产物和适用约束明确。
- 前置条件、精确顺序、健康/监控、恢复检查和不可逆限制有依据。
- 未决缺口与影响明确，准备状态未冒充已执行，手册和必要附件实际可取。

用户只要准备时交付手册与缺口，在此结束。当前任务已明确授权执行且对应条件满足时继续 [EXECUTE](../sprite-devops-execute/SKILL.md)，不重复询问；需要处理现有故障时进入 [RECOVER](../sprite-devops-recover/SKILL.md)。
