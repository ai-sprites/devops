# RECOVER — 核对状态并恢复

**输入：**失败证据或明确恢复请求、当前环境/版本、发布执行记录、恢复步骤与授权、兼容和数据约束。

**输出：**真实恢复或受阻结果、恢复后检查，以及项目现有手册中可追溯的执行与恢复证据。

## 1. 查清当前状态与失败范围

读取原请求、发布手册、实际执行记录、失败现象和可用系统信号，确认目标环境、当前版本、已经生效及结果未知的步骤。可能重复发布或产生数据副作用的操作先查实际状态，不能因为失败返回就假设未执行，更不能盲目重跑。

记录影响、证据或未知，以及已知负责对象或下一项检查。按 [工作方法](../sprite-devops-release/references/workflow.md)的执行边界核对当前恢复任务，沿用已有授权、决定人及来源；仅诊断/评审不能扩大为未要求的生产或外部变更。

## 2. 选择适用于实际状态的恢复步骤

对照手册的恢复触发、步骤和恢复后检查，确认其仍适用于当前环境、版本及兼容窗口；手册有缺口时仅补所需准备。区分应用回退与数据恢复：回退应用不能找回已删除或覆盖的数据；核对可逆性、实际可用备份、恢复范围和不可恢复影响。

多服务或数据变化按实际依赖和执行顺序恢复，不能默认回退所有组件。未演练步骤保持未验证，不能把命令存在当成已证明可恢复或无损承诺。需要改变目标、接受新风险、缺少关键备份/访问或放行条件时说明具体影响，只暂停依赖操作，其余调查和准备继续。

## 3. 在当前授权内执行恢复

当前已有明确恢复授权且条件满足时，按经核实的步骤执行，不重复索取许可。记录实际对象、版本、精确命令或操作、时间、结果和证据，不暴露秘密。只有必须由有权的人作出的决定仍缺失时才提出具体问题，得到答案后将选择、决定人及来源写回手册。

恢复中出现未知结果先核对状态再判断后续动作；不能无界重试或把部分恢复描述为全部成功。无法验证的外部步骤记录原因及影响，不编造仪表盘、负责人、批准或结果。

## 4. 验证恢复结果与剩余影响

执行约定的恢复检查、健康检查和必要监控观察，核对恢复目标、实际版本、数据状态及重要兼容行为。只对有证据支持的部分给出恢复结论；尚未恢复、未验证或仍受影响的内容写清范围与下一步。

既有记录中的发布证据、第一次失败、恢复动作与恢复验证分别保留。恢复方案未执行就标为准备，未演练不能写成演练通过；只读分析在当前回复记录适用结果即可，不造执行证据。

## 5. 更新记录并交接

按 [模板与交付](../sprite-devops-release/references/delivery.md)更新同一业务手册，补充实际失败状态、采用恢复路径、决定来源、精确操作、检查与限制。手册原位维护，必要日志、截图和附件沿用项目证据位置，保留真实来源版本。

交付真实链接、仓库、相对 Git 根路径及当前状态，区分已保存、已提交和远端可获取。旧结论只有仍适用时沿用，不冒充重新验证；不能保存或读取时说明具体限制，继续不受影响的工作。

## 完成条件与下一步

- 当前发布与数据状态已核对，恢复范围、权限和限制明确。
- 已授权恢复与相应检查完成，或受阻部分、影响及缺失决定/访问具体可见。
- 失败、恢复操作、恢复后验证和剩余影响可追溯，未验证项如实保留。

交付恢复结果与具体后续检查。修复后重新发布须回到 [PREPARE](../sprite-devops-prepare/SKILL.md)核对变化，再按当前明确授权进入 [EXECUTE](../sprite-devops-execute/SKILL.md)；恢复完成本身不产生新发布授权。
